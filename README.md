# MLops_my — учебный проект по MLOps

Учебный репозиторий Арсения Воронова: бинарная классификация на синтетических данных, обучение нейросети на PyTorch, тестирование ML-компонентов и примеры трекинга экспериментов в MLflow.

Проект демонстрирует отдельные этапы ML-разработки: подготовку данных, построение модели, обучение, оценку и сохранение артефактов. В репозитории также есть заготовка DVC-пайплайна и конфигурации инструментов качества кода.

> **Статус:** проект находится в разработке. Базовые компоненты можно использовать через пакет `scr`, но тесты и некоторые сценарии требуют согласования путей и интерфейсов. Известные ограничения описаны ниже. Подтверждённые результаты обучения и покрытия тестами пока не опубликованы.

## Возможности

- Генерация воспроизводимого синтетического датасета с заданным seed.
- Полносвязная нейросеть с ReLU и опциональным Dropout.
- Обучение с Adam и `CrossEntropyLoss`.
- Расчёт loss и accuracy, проверка обучения на одном батче.
- Пример ручного логирования параметров, метрик и модели в MLflow.
- Пример автоматического логирования с PyTorch Lightning.
- Модульные, property-based и сквозной тесты.
- Заготовка двухэтапного DVC-пайплайна.

## Данные и модель

### Датасет для нейросети

`SyntheticDataset` создаёт признаки из стандартного нормального распределения. Метка определяется правилом:

```python
label = 1 if sum(features) > 0 else 0
```

По умолчанию создаются 100 объектов с четырьмя признаками и `random_seed=42`. В MLflow-сценариях используются 200 объектов с восемью признаками.

Метод `split(train_ratio=0.8, seed=42)` возвращает две подвыборки PyTorch `Subset`. `build_dataloader()` объединяет объекты в батчи; последний неполный батч сохраняется.

### Классификатор

`SimpleClassifier` выполняет следующие преобразования:

| Этап | Операция |
| --- | --- |
| Вход | Тензор размера `[batch_size, input_features]` |
| Скрытый блок | `Linear → ReLU → Dropout` либо `Identity`, если Dropout выключен |
| Выходной слой | `Linear(hidden_size, num_classes)` |
| Результат | Логиты размера `[batch_size, num_classes]` |

Для получения класса используется `logits.argmax(dim=1)`. Перед `CrossEntropyLoss` применять softmax не нужно: функция принимает логиты.

### Отдельный CSV-пример

`generate_data.py` создаёт 100 строк с колонками `feature_a`, `feature_b`, `label`. Признаки лежат в диапазоне от 0 до 10, метка равна 1 при сумме признаков больше 10.

Этот CSV используется в заготовке DVC-пайплайна. Текущие скрипты обучения генерируют данные в памяти и **не читают этот файл**.

## Быстрый старт: базовое обучение

Пример ниже использует фактический интерфейс `Trainer` и текущий пакет `scr`. Он не требует исправления MLflow-скриптов или запуска DVC.

### 1. Клонирование и окружение

```bash
git clone https://github.com/sunlite63/MLops_my.git
cd MLops_my
python -m venv .venv
```

Активация в Linux / macOS:

```bash
source .venv/bin/activate
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установите PyTorch и перейдите в каталог ML-проекта:

```bash
python -m pip install --upgrade pip
python -m pip install torch
cd "Новая папка"
```

Это минимальное окружение для примера, без фиксации версии PyTorch. Для воспроизводимых экспериментов необходимо отдельно согласовать версии ML-зависимостей и зафиксировать их в lock-файле. Корневой `uv.lock` описывает другое окружение.

### 2. Обучение и оценка

Запустите `python` из каталога `Новая папка` и выполните:

```python
import torch

from scr.dataset import SyntheticDataset, build_dataloader
from scr.models import SimpleClassifier
from scr.trainer import Trainer

# Создаём один набор данных и разделяем его до обучения.
dataset = SyntheticDataset(n_samples=1000, n_features=8, random_seed=42)
train_data, valid_data = dataset.split(train_ratio=0.8, seed=42)

train_loader = build_dataloader(train_data, batch_size=32, shuffle=True)
valid_loader = build_dataloader(valid_data, batch_size=32, shuffle=False)

torch.manual_seed(42)
model = SimpleClassifier(input_features=8, hidden_size=32, num_classes=2)
trainer = Trainer(model=model, lr=0.01)

history = trainer.fit(train_loader, epochs=10)
print("Последняя эпоха:", history[-1])
print("Валидация:", trainer.evaluate(valid_loader))

model.eval()
with torch.no_grad():
    features, target = valid_data[0]
    logits = model(features.unsqueeze(0))
    print("Предсказание:", logits.argmax(dim=1).item())
    print("Истинный класс:", target.item())
```

`fit()` возвращает список словарей с ключами `epoch` и `loss`; `evaluate()` — словарь с `loss` и `accuracy`. Численные результаты зависят от окружения и запуска; заранее заданное качество не гарантируется.

### 3. Генерация CSV

Из каталога `Новая папка`:

```bash
python scr/generate_data.py
```

Результат появится в `data/raw_data.csv` относительно текущего рабочего каталога.

## MLflow: трекинг экспериментов

В репозитории представлены два сценария:

| Сценарий | Эксперимент | Параметры запусков | Логирование |
| --- | --- | --- | --- |
| `train.py` | `pytorch_classifier_manual` | 10 эпох; learning rate 0.05 и 0.005 | Параметры, `train_loss`, итоговые метрики, веса и модель |
| `train_autolog.py` | `pytorch_lightning_autolog` | 5 эпох; learning rate 0.02 и 0.002 | MLflow autolog; тренировочные loss и accuracy |

Оба сценария обращаются к tracking server по адресу `http://localhost:5000`. Адрес задан константой в коде.

Для подготовки окружения и локального сервера:

```bash
python -m pip install mlflow pytorch-lightning
mlflow server --host 127.0.0.1 --port 5000
```

Интерфейс доступен по адресу [http://localhost:5000](http://localhost:5000). Сервер оставьте работающим в отдельном терминале.

**Перед запуском сценариев необходимо исправить импорты `src` и, для ручного трекинга, вызовы `Trainer`.** Один вариант — заменить `from src...` на `from scr...` во всех скриптах и тестах. После этого для `train.py` требуется следующая адаптация:

| Сейчас в скрипте | Фактический интерфейс |
| --- | --- |
| `Trainer(model=model, learning_rate=learning_rate)` | `Trainer(model=model, lr=learning_rate)` |
| `trainer.train_loop(loader, num_epochs=1)` | `trainer.fit(loader, epochs=1)` |
| `results[0].loss` | `results[0]["loss"]` |
| `trainer.validate(loader)` | `trainer.evaluate(loader)` |
| `eval_result.loss`, `eval_result.accuracy` | `eval_result["loss"]`, `eval_result["accuracy"]` |

После внесения этих изменений запуск из каталога `Новая папка`:

```bash
python -m scr.train
python -m scr.train_autolog
```

В ручном сценарии предусмотрено сохранение весов в `output/model_weights.pt`. Последующий эксперимент перезаписывает локальный файл, а MLflow получает артефакт в рамках отдельного run.

В исходном ручном сценарии итоговая оценка проводится на обучающих данных. Она не измеряет обобщающую способность модели. Для оценки качества используйте отдельную выборку, как в примере быстрого старта. В Lightning-сценарии отдельная валидация пока не реализована.

## Тестирование

Тесты используют pytest и Hypothesis. В текущем состоянии их сборка блокируется импортами `src`; сквозной тест дополнительно использует устаревший интерфейс `Trainer`.

После согласования импортов и адаптации `test_e2e.py` к `fit()` / `evaluate()` и словарям результатов:

```bash
# Выполнять из каталога «Новая папка».
python -m pip install pytest hypothesis pytest-cov
python -m pytest tests -v
python -m pytest tests -m unit -v
python -m pytest tests -m property -v
python -m pytest tests -m e2e -v
python -m pytest tests --cov=scr --cov-report=term-missing
```

Существующие проверки охватывают форму выхода `DenseBlock`, работу блока с Dropout, разные размеры тензоров через Hypothesis, функцию `calculate_sum` и сквозной сценарий обучения.

Файлы `test_block.py`, `test_model.py`, `test_train.py` и `test_dataloader.py` сейчас содержат одинаковые проверки `DenseBlock`. Их названия не означают, что загрузчик данных и весь цикл обучения покрыты отдельными модульными тестами. Маркеры `smoke` и `overfit` объявлены в конфигурации, но соответствующие маркированные тесты пока отсутствуют.

Порог accuracy > 0.8 в сквозном тесте проверяется на обучающем наборе: это диагностическая проверка, а не результат независимой оценки.

## DVC-пайплайн

Файл `scr/dvc.yaml` описывает два этапа:

| Этап | Предусмотренное действие | Выход |
| --- | --- | --- |
| `create_dataset` | Генерация CSV через `src/generate_data.py` | `data/raw_data.csv` |
| `compute_metrics` | Обработка через `src/process_data.py` | `output/metrics.json` |

Пайплайн пока не готов к `dvc repro`: пути не соответствуют текущей структуре, `process_data.py` отсутствует, конфигурация `.dvc` не добавлена. Кроме того, расположение YAML внутри `scr` влияет на разрешение относительных путей.

Для завершения интеграции нужно разместить `dvc.yaml` в рабочем корне ML-проекта либо явно задать рабочую директорию, согласовать пути, реализовать `process_data.py` с оговорёнными метриками и инициализировать DVC. Обучение модели сейчас не включено в DVC-пайплайн.

## Проверка качества кода

В корне репозитория настроены Ruff и ty. При установленном uv:

```bash
uv sync
uv run ruff check .
uv run ty check
```

Эти команды запускают проверки, но не гарантируют их успешное прохождение. Корневое окружение не включает PyTorch и остальные ML-зависимости, необходимые для полноценной проверки ML-кода.

## Известные ограничения и дальнейшие шаги

1. **Согласовать структуру пакета.** Код находится в `scr`, а импорты и настройки setuptools указывают на `src`. Во вложенном `pyproject.toml` также указан отсутствующий рядом `README.md`. Установка ML-проекта как пакета требует доработки конфигурации.
2. **Унифицировать интерфейс обучения.** Обновить `train.py` и `test_e2e.py` под фактический API `Trainer`.
3. **Зафиксировать ML-окружение.** Проверить совместимость ограничений версий во вложенном `pyproject.toml` и создать lock-файл для ML-зависимостей.
4. **Завершить DVC-пайплайн.** Добавить отсутствующий этап обработки, корректные пути и при необходимости обучение.
5. **Расширить тесты.** Заменить дубли проверками DataLoader, обучения, градиентов и переобучения на одном батче; исправить аннотацию результата `SyntheticDataset.split()` на `Subset`.
6. **Добавить независимую оценку.** Использовать train/validation/test и логировать в MLflow метрики на отложенных данных.
7. **Автоматизировать проверки.** Добавить CI с линтингом, проверкой типов и тестами. Сейчас workflow CI, Docker-конфигурация и сервис инференса в репозитории отсутствуют.
